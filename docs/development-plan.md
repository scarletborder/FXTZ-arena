# 肥乡天则: ARENA 开发路线图

## 目标

实现一个 16:9、Phaser 渲染、Rapier 2D 物理、确定性 60fps tick 的 2D 弹幕对战格斗游戏。玩家选择两名角色和若干能力卡，在联机、人机或靶场中进行战斗。联机使用 WebTransport 长连接，战局同步使用 Lockstep + Rollback Netcode。

## Monorepo 包规划

### `packages/types`

共享类型和静态数据 schema。

- 角色、能力卡、地图、房间、玩家配置、输入帧、战局事件、结算统计。
- 不引入运行时依赖，避免循环依赖。
- 导出纯 TypeScript 类型、枚举、常量和校验辅助。

### `packages/raid-logic`

确定性战局核心。

- 60fps frame tick 游戏循环。
- 输入队列、输出事件队列。
- 角色移动、转向、射击、装弹、bomb、切换模式。
- 子弹、激光、魔炮、清弹、无敌、冻结等效果。
- Rapier 2D 物理封装，但对外暴露确定性状态。
- 状态快照、回滚、重放、debug hash。
- 人机和靶场 mock server 可直接复用。

### `apps/frontend`

Phaser 前端。

- 首页、设置、图鉴、战斗入口、选择、加载、战局、结算 scene。
- 只使用 Phaser 渲染 UI 和游戏画面。
- 采集键鼠输入并转换为 frame input。
- 渲染 `raid-logic` 输出状态和事件。
- debug 模式显示最近 10 帧 hash。

### `apps/dedicated-server`

Node.js 专用服务器。

- WebTransport 连接管理。
- 房间创建、列表、密码、快速匹配、准备、加载同步。
- 转发输入帧和同步控制消息。
- 不直接执行权威战斗逻辑，除非后续要加入服务端裁决模式。

## 开发里程碑

### M0：仓库与工程基线

交付：

- Turborepo workspace。
- TypeScript、ESLint、Prettier、Vitest 基线。
- `types`、`raid-logic`、`frontend`、`dedicated-server` 四个包。
- 公共脚本：`dev`、`build`、`test`、`lint`。

验收：

- 所有包能构建。
- `frontend` 能启动 Phaser 空 scene。
- `raid-logic` 有一个可运行的固定 tick 示例。

### M1：共享数据与内容基线

交付：

- 角色、能力卡、地图、房间、输入帧、战局状态的数据结构。
- 默认角色：博丽灵梦、魔理沙、咲夜。
- 默认设置：cost 上限 10、命数 2、bomb 3。
- 数值单位换算：速度档位、秒到 frame tick、判定圆直径倍数。

验收：

- 静态内容可由 `types` 导入。
- cost、选择合法性、默认命数和 bomb 规则有单元测试。

### M2：确定性战局循环

交付：

- 基于 frame tick 的主循环。
- 玩家输入状态：移动、朝向、射击、bomb、装弹、切换角色、tab 信息显示。
- 状态快照、回滚接口、重放接口。
- 每帧 deterministic hash。

验收：

- 同一输入序列在多次运行中生成完全相同的 hash 序列。
- 回滚到旧帧再重放后，当前状态 hash 与原结果一致。

### M3：基础战斗原型

交付：

- 三角形角色、常驻红色判定点。
- 移动、转向、普通射击、弹夹、装弹。
- 命数、伤害、死亡、结算。
- 下方双方信息 HUD、准心、弹夹竖条、bomb 图标。

验收：

- 靶场中可选择两名角色进入战局。
- 子弹命中判定点后扣命。
- 弹夹耗尽后点击射击触发红色闪烁反馈。

### M4：角色技能与 bomb

交付：

- 博丽灵梦诱导弹与清弹 bomb。
- 魔理沙高速激光、魔炮前摇、持续、无敌、动作锁定。
- 咲夜双弹、时间停止 bomb。
- 清弹、无敌、冻结、暂停子弹等效果统一以 tick 表达。

验收：

- 三个角色的普通射击和 bomb 行为符合 [游戏规则规格](./rules.md)。
- 所有效果在回滚重放后 hash 稳定。

### M5：选择、图鉴与本地模式

交付：

- 首页、设置、图鉴、开始战斗。
- 选择页面：拖拽两名角色、选择能力卡、cost 预览、确认出战。
- 人机对战：CPU 从预设配装中选择。
- 靶场：无视 cost，支持任意两名角色和无限能力卡。

验收：

- cost 达到或超过上限时确认按钮不可用。
- 不允许选择两个同一角色。
- 图鉴可按一级和二级分类浏览角色与能力卡。

### M6：专用服务器与房间系统

交付：

- WebTransport 服务。
- 房间创建、密码、房间列表、快速匹配。
- 准备同步、加载同步、战局启动。
- 客户端连接状态驱动按钮可用性。

验收：

- 前端连接专用服务器后创建房间按钮可用。
- 快速匹配只加入无密码房间。
- 双方准备并加载完成后进入同一战局 frame。

### M7：Rollback 联机整合

交付：

- 接入本地 `D:\code\js\rollback-netcode`。
- 输入延迟、预测输入、回滚重放。
- 同步检查和 debug hash 展示。
- 网络断线、超时、重连策略草案。

验收：

- 两个浏览器实例在同一输入序列下状态 hash 一致。
- 人为加入延迟和抖动后，战局可回滚修正。

### M8：测试、调试与内容扩展

交付：

- 确定性测试套件。
- 角色技能回归测试。
- 房间协议集成测试。
- 性能指标：60fps、回滚窗口、快照内存。
- 第一批能力卡实现。

验收：

- CI 可跑通 build/test/lint。
- debug 模式右上角显示最近 10 帧 hash。
- 每个角色和能力卡都有图鉴条目与数据定义。

## 优先级

1. 先实现 `types` 和 `raid-logic`，保证战斗规则可测试。
2. 再用 Phaser 做靶场，最早形成可玩闭环。
3. 房间和联机在本地模式稳定后接入，避免 UI 与 netcode 同时不稳定。
4. 能力卡应在角色基础完成后加入，否则 cost 和选择页面会过早复杂化。

## 风险与对策

- WebTransport 浏览器支持和证书配置复杂：先做本地 mock transport，再接真实 WebTransport。
- Rapier 2D 可能引入非确定性：将物理输入和输出量化为整数或 Decimal，并用 hash 测试锁定。
- Rollback 快照成本高：状态结构从一开始保持纯数据、可序列化、可复制。
- Phaser UI 复杂度高：scene 间状态统一走轻量 router/state machine，避免 UI 状态散落。
