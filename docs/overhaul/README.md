# FXTZ Arena 重构总览

本目录是项目架构重构的唯一计划与记录入口。目标是在保持确定性战斗结果和现有玩法的前提下，把逻辑、渲染、网络放到清晰的模块接缝之后，使三者能够独立测试和替换。

## 当前判断

仓库已经有正确的顶层方向：`@repo/raid-logic` 承载确定性战斗逻辑，`apps/frontend` 承载 Phaser 客户端，`apps/dedicated-server` 承载服务器。但客户端组合层仍存在三类高耦合热点：

1. `BattleScene` 同时创建输入、固定帧运行时、回滚、联机、视图、音频和结算模块，并用大量互相捕获的回调解决初始化顺序。
2. 固定帧、回滚和联机同步原本分散在多个 manager 与 adapter，并通过互相捕获的回调维持初始化顺序。
3. 视图仍直接读取完整战斗领域输出，渲染投影边界尚未建立。

## 目标依赖方向

```text
Phaser Scene / UI ──adapter──> Application Modules ──> @repo/raid-logic
                                  │
Network Transports ──adapter──────┘
```

- 逻辑模块不得导入 `phaser`、浏览器传输实现或具体场景。
- 渲染模块只消费不可变的战斗输出和视图模型，不推进战斗状态。
- 网络模块通过输入帧、确认帧和连接状态接口协作，不直接创建 Phaser 对象。
- 场景是组合根，只负责装配 adapter、生命周期和转场。
- 新模块以其公开接口作为测试面，不测试内部实现。

## 执行阶段

| 阶段 | 接缝       | 交付物                                             | 状态   |
| ---- | ---------- | -------------------------------------------------- | ------ |
| 0    | 基线       | 耦合清单、依赖规则、验证命令                       | 已完成 |
| 1    | 战斗帧管线 | 从 Phaser adapter 提取纯固定帧模块和接口测试       | 已完成 |
| 2    | 联机呈现   | 从 `BattleNetworkManager` 提取状态呈现与调度接口   | 已完成 |
| 3    | 战斗会话   | 用单一会话模块封装运行时、同步和回滚协作           | 已完成 |
| 4    | 渲染投影   | 将战斗输出转换为稳定视图模型，减少视图读取领域结构 | 已完成 |
| 5    | 场景组合根 | 将 `BattleScene` 收敛为装配、生命周期和渲染提交    | 已完成 |
| 6    | 依赖守卫   | 添加导入规则与架构测试，阻止耦合回流               | 已完成 |

每一阶段必须满足：行为测试先覆盖新接口；迁移所有调用者；删除被替代的旧逻辑；通过目标包的测试、类型检查和 lint。详细决策、目标目录和进度分别记录在 [architecture.md](./architecture.md)、[directory-structure.md](./directory-structure.md) 与 [progress.md](./progress.md)。
